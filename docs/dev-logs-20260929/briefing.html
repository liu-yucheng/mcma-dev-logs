🎯 Success Rates

The data below comes from the attempt records in each <model>/<problem> folder. One retry is one extra chat_<timestamp>/ record for that problem. A case is scored “solved” when the agent produced a plot within 5 attempts. In a solved session, the last chat_<timestamp>/ record (in natural order) is the successful attempt. Its final solution carries the graphical plots. Every earlier attempt failed. The explorer’s remarks.html records each attempt with that convention.

First-attempt means the agent solved the problem with one attempt. Total attempts counts every attempt, including retries. Across the 5 MCMA configurations, the runs totaled 141 attempts over 120 cases. 118 cases produced a plot within 5 attempts (98%). 108 were solved on the first attempt (90%).

🔁 Re-attempts

MCMA agents re-attempted 21 times over the 120 cases. The re-attempts are spread unevenly. 18 of the 21 come from gemma-4-26b-a4b-it. Two of that model’s problems (15.7.23 and 15.7.50) never produced a plot in any of their five attempts. These two problems are the whole cause of the 2 unsolved cases.

  1. No plot in the solution. The workflow requires the final answer to include plots. On 15.7.23 and 15.7.50, gemma-4-26b-a4b-it chose not to include any image in any of its 5 attempts. The agent kept retrying and still submitted a text-only answer.
  2. First-attempt gap. The remaining re-attempts were few. glm needed a second pass on 2 problems. MiniMax needed a second pass on 1 problem. On the next attempt, they produced the required plot.

The remarks.html page of each solved session marks every attempt before the last one as failed and the last one as worked. In the two gemma manual cases, all five attempts are marked failed.

We call an attempt “Agents worked as expected” when the model produces multimodal contents, that is text and image, as the final solution of a problem. We use this term regardless of the mathematical correctness of the output. We need to manually compare model output against canonical solutions to check mathematical correctness.

💰 Cost-effectiveness

Cost is the estimated spend to reach each configuration’s success rate. Costs read from each costs.json. Peak-hour vs off-peak pricing matters only for the two deepseek-flash configurations. The other models quote a flat rate. Exchange rate used: 1 CNY = 0.15 USD (1 USD = 6.71 CNY), dated 20260928_utc_0800. The trade is plain. The run that produced cheap plots read the least context. The cheapest run, gemma-4-26b-a4b-it at 0.50 USD, still solved 22 of its 24 problems at a 91.7% success rate.

Tools took the same model from 0 to 24 solves for less than a dollar extra.

🔢 Token Usage

Token counts are round-trip totals across recorded chat attempts (one per retry, matching the attempt data in the Success Rates section). The input token totals include the cached-context reads that the API reports. The output token totals break out reasoning tokens where a model reports them. The MCMA agents read far more context than they write because each message re-sends the ongoing plan, the tool transcripts, and the prompt. Input dominates every run.
