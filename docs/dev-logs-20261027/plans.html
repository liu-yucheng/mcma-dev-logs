🗺 The Roadmap

📌 The plans follow the order below. Plans 3 and 4 are enablers. They make Plans 1 and 2 cheaper and more stable.

  1. 🧑‍🏫 Make a multimodal AI math tutor. → Plan 1.
  2. 📝 Make a multimodal AI math grader. → Plan 2.
  3. 🐢 Replace PowerShell with Git Bash. → Plan 3.
  4. 📜 Replace full LaTeX with Typst + mitex. → Plan 4.

💡 The run already gives the base for Plan 1 and Plan 2. Each solution is detailed and computationally verified. Each solution also has tutorial content about how to approach similar problems.

🧑‍🏫 Plan 1. Make a Multimodal AI Math Tutor

🎯 Goal

Turn the agent into a multimodal AI math tutor. The tutor reads a problem image, solves the problem, and teaches the method.

🔧 Actions

🧮 Keep the verified workflow. Read the image, solve, verify with Python, draw the figures, and compile the result.

💬 Add a dialog. Ask the student what they tried. Give hints before the full solution. Let the student ask questions at each step.

📚 Use the tutorial sections. The current output already explains the symbols and shows how to solve similar problems. The tutor reuses that content.

🧪 Check each hint. The agent verifies a hint with Python before it sends the hint.

🧑‍🎓 Test with students. Use new problems and student questions. Check that the hints are correct and useful.

✅ Outcome

A tutor that gives correct answers and teaches the method. The student learns how to approach the next problem, not only this problem.

📝 Plan 2. Make a Multimodal AI Math Grader

🎯 Goal

Then make the agent a multimodal AI math grader. The grader reads a photo of student work and gives a score with reasons.

🔧 Actions

📋 Define a rubric. Write the score points for each problem. Include the method, the steps, and the final answer.

🔍 Read the student steps. The agent reads the work from the image and writes the steps in a machine-readable form.

🧮 Check the math. The agent checks each step with Python and symbolic math. A correct final answer does not hide a wrong step.

⚖️ Compare the methods. Compare the student method with the canonical method. Give part credit for a valid method that differs from the canonical method.

💬 Write feedback. Name the error. Show the fix. Keep the feedback short and clear.

🧪 Measure agreement. Compare the agent scores with human scores. Record the differences.

✅ Outcome

A draft grader with evidence, part credit, and feedback. A human teacher stays in the loop.

⚠ Grading is harder than solving. The agent must judge work that is not its own. A wrong step can look correct in an image. The Python checks and the human review are necessary.

🐢 Plan 3. Replace PowerShell with Git Bash

🎯 Goal

Remove the PowerShell overhead. The DSH PowerShell support causes recurring command-exception cycles. The cycles add tokens and time to each step.

🔧 Actions

📦 Install the plugin. Add dsh-gitbash-new to the DSH profile.

🐢 Install Git Bash. Install Git for Windows and use its Bash shell.

🛠 Install MSYS2. Add the MSYS2 tools that the shell commands need.

🔄 Route the shell calls. Send the agent shell calls through Git Bash, not PowerShell.

🧪 Re-run the suite. Run the 24 problems again. Compare the tokens, the time, and the cost with this run.

✅ Outcome

Fewer retries and less overhead on Windows. The agent and the prompt stay the same. The shell becomes stable.

📌 This fix is for Windows only. The remark file names the DSH PowerShell support as the cause of the 3 times more tokens and the 3 times more time. The measured values are in the Results Briefing.

📜 Plan 4. Replace Full LaTeX with Typst + mitex

🎯 Goal

Replace full LaTeX support with Typst and mitex. The run crashed one time with an out-of-video-memory error. Too many concurrent LaTeX compilation processes caused it.

🔧 Actions

📄 Convert the document. Write the solution as a Typst document.

➕ Convert the math. Use mitex for the LaTeX math expressions.

📈 Keep the figures. Keep the Python figure scripts and the PNG files. Insert the figures near the related steps.

⚙ Compile with Typst. Compile each solution to a PDF. Check the math, the figures, and the labels.

🧪 Re-run in parallel. Run the 24 problems with parallel jobs. Watch the video memory.

✅ Outcome

A lighter compile step. The run uses less video memory and does not crash from concurrent LaTeX jobs.

📌 The solution content does not change. Only the typesetting engine changes. The PDFs stay the final output.
