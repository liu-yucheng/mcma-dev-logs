🎨 Plan 1. Revise Math-Tutor Prompts for Plot Quality Week 1–2

📌 The current prompts are minimalist prompts. They produce plots of correct geometric objects. But their low visual quality (2D and 3D perspectives, projections, colors, transparencies) makes them unusable. They cannot help readers gain a more intuitive understanding of the problem. This plan targets the visual quality, not the math.

🤖 RSI: LLM (Internet) + DeepSeek Harness (PC, PTC mode) + Python (numpy, sympy, matplotlib) + HTML (KaTeX) 🖥 Deployment test: LLM (HPC) + DeepSeek Harness (HPC, PTC mode) + Python (numpy, sympy, matplotlib) + HTML (KaTeX)

🎯 Goal

Revise the math-tutor agent prompts for better math plot visual quality. Use DeepSeek Flash (Internet) for human-involved recursive self-improvement (RSI). Use Qwen3.8-27B (HPC) for deployment testing.

🔧 Actions

🤖 Run the RSI loop. Use DeepSeek Flash (Internet) with the PC harness in PTC mode. Keep a person in the loop for each prompt revision.

🖥 Test on the deployment recipe. Use Qwen3.8-27B (HPC) with the HPC harness in PTC mode, so the prompt is checked on the target path.

🎨 Target the visual gaps. Work on 2D and 3D perspective, projections, colors, and transparencies.

🧪 Compare the plots. Run the revised prompt on the same problems. Put the old plot and the new plot side by side.

✅ Keep the geometry correct. Accept a prompt only if the geometric objects stay correct and the plots become clearer.

✅ Outcome

A revised prompt set that produces plots with clear perspective, projection, colors, and transparency. The RSI stays human-involved. The deployment test on Qwen3.8-27B shows whether the prompts hold on the HPC recipe.

⚠ Do not trade correctness for looks. The current prompts already produce the correct geometric objects. A revised prompt must keep that correctness and raise only the visual quality.

📌 Why the plots matter. A correct plot that hides the perspective or the projection does not build intuition. The reader gains more from a clear figure than from a correct but flat one.

🖥 Plan 2. Move DeepSeek Harness to the HPC Week 1–2

📌 Today the harness runs on the PC, and the model runs on the HPC. Every model request crosses the network. This plan puts 1 DeepSeek Harness instance on the HPC, next to the model.

⚡ Plan 3. Increase Inference Speed on the 8 × A800 Node Hard

🐌 The limit is real

📌 The A800 has only 20 TFLOPS of processing power. That value is low for a 27-billion-parameter model at BF16 precision.

📈 Measured averages for Qwen3.8-27B (BF16): on 1 A800, the inference speed is 27 tokens per second. On 2 A800, it is 47 tokens per second.

⚠ The gain from 1 GPU to 2 GPUs is real but modest. A large gain will be difficult. This plan measures small gains and removes waste. It does not promise a fast model.

🎯 Goal

Measure the current speed. Test the safe options. Find the best setting for a 24-problem run on this node.

✅ Outcome

A measured speed table. A recommended setting for the next 24-problem run. A clear statement of the limit, so the team does not plan around a gain that the hardware cannot give.

🔧 Actions

📈 Measure the baseline. Record the prefill speed, the decode speed, the time to the first token, and the tokens per second on 1 A800.

🧮 Test the server settings. Test prefix caching, chunked prefill, the batch size, the number of concurrent sequences, and the GPU memory fraction. Change one setting at a time.

🤝 Test 2 A800. Use tensor parallelism across 2 GPUs. Measure the tokens per second. The measured average is 47 tokens per second, against 27 on 1 GPU.

📦 Test a smaller number format. Test FP8 or INT8 quantization, or an AWQ/GPTQ build. Run 2 problems and compare the math and the figures with the BF16 output before you accept a loss.

📜 Reduce the context. Send a shorter prompt and keep the instructions stable, so the prefix cache can hit.

🔄 Reduce the work. Fewer steps and shorter verification text can do more than a server flag.

🔒 Isolate the server. Do not run grading tasks in the same process. A refused connection adds a retry and hides the real speed.
