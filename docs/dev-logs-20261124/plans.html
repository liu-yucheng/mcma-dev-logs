📚 1. Survey recursive visual refinement Top priority

🔍 Check the latest dynamics in the research community. Read the recent literature and public work on agents that write plotting code. Look for works about how an AI agent recursively refines the visual quality of code-generated math plots.

📋 Record the method. For each work, note the refinement loop (what the agent changes), the feedback signal (human, model, or image metric), the benchmark, and the failure modes.

✅ Decide what to reuse. Pick the one or two methods that fit our harness and our canonical-figure baseline. Write the reason in the plan.

📌 First check: a short annotated list of relevant works, plus a decision on the first method to test.

🎨 2. Hand-build the plot recipe Top priority

🧭 Pick a few plotting problems. Use problems that need a solid, a cut, and a projection. Start from the two transfer examples, 15.7.18 and 15.7.32, and add one more if needed.

🔧 Refine the prompt by hand. Work manually or interactively, one requirement at a time, until the agent writes code that produces the figures in the requirement table. Keep the instructions short and explicit.

🎨 Check every view. A figure is accepted only if all three view groups pass. Do not trade one view for another.

📌 First check: one prompt set that gives all three view groups on all chosen problems, with a side-by-side figure record.

🎨 Plan 1. Restore the Classic Plotting Prompts Next

📌 The old DeepAgents-based MCMA system message had explicit plot requirements. It required, for every 3D problem, one 3D pyplot plot, one 3D PGFplots plot, one 2D pyplot plot, and one 2D PGFplots plot. The v17 figure law dropped that requirement. The result is clear in 15.7.18: one 3D panel, two labels on the wrong surface, no projection.

🤖 RSI: LLM (Internet) + DeepSeek Harness (PC, PTC mode) + Python (numpy, sympy, matplotlib) + HTML (KaTeX)

🎯 Goal

Restore the classic plot prompts and keep the v17 label law. The target is a labelled projection plus a labelled solid for every 3D problem.

🔧 Actions

📜 Copy the old rules. Take the plot rules from system_message.md and add them to the v17 figure law.

📈 Require the pair. Require one 3D view and one labelled 2D projection for every 3D problem.

🎨 Keep the label law. Keep arrowheads, label-on-surface, closure, and clearance checks.

🧪 Re-run 15.7.18 and 15.7.32. Use the same problems, so the old and new figures compare directly.

✅ Outcome

A figure law that produces a labelled projection panel and a labelled solid on the hard 3D problems. The 15.7.18 perspective failure becomes the first regression test.

🔧 Plan 2. Make the RSI Learn Explicitly Next

📌 The current loop writes free text into the prompt. The loss is a five-dimension rubric average. It cannot say which rule caused a gain, and it cannot say whether the plot improved. The prompt grew from 272 to 11,952 characters in prompt.extra, and the final pass had the worst loss of the run.

🎯 Goal

A training signal that reflects the learned skill, especially the plot skill, and a record of which rule came from which defect.

🔧 Actions

📈 Split the loss. Report correctness, verification, and figure quality as separate numbers. Do not average them into one value.

🎨 Add a figure score. Score label placement, projection presence, axis arrowheads, closure, and clearance as named checks.

📋 Keep a rule ledger. Each backward pass adds one rule with the problem and defect that caused it. A later pass can cite it.

✅ Keep the gate. A rule is accepted only if the release gate still passes and the figure score rises.

💡 Why explicit matters. The transfer failed because the learned rule was prose. A slower model read the prose and did not apply it. An explicit rule with a named check, a target, and a before/after figure is easier to carry across models.

🖥 Plan 3. Deploy DeepSeek Flash or a Distilled Version on the HPC Hard

📌 DeepSeek Flash is the only model with acceptable tutor speed today: about 200 tokens/s, and under 5 minutes per problem with RSI off. The model is served from the Internet. This plan tests whether it can move to the HPC.

OptionHardwareExpected speedExpected quality
🖥 Full parameter versionGPU + CPUExtremely low throughputClose to the Internet model
📦 Distilled versionGPU onlyHigher throughputSignificant performance degradation

🎯 Goal

A local DeepSeek Flash endpoint that a tutor product can call without the Internet API.

🔧 Actions

📈 Measure the full version. Record tokens/s and time per problem on the GPU + CPU path.

📦 Measure a distilled version. Record the speed gain and the loss on the 7 test problems.

🧪 Compare on the same problems. Use the 7 test problems and the two transfer examples.

🔧 Decide with numbers. Accept a distilled model only if the math stays correct and the plot quality stays close.

⚠ The full version is likely too slow. The manual remarks expect extremely low throughput on GPU + CPU. This plan measures it first, so the team does not plan a tutor service around a model that cannot serve one.

🧠 Plan 4. Find a Coding- or Math-Enhanced Qwen3.8-27B Hard

📌 The current Qwen3.8-27B is not acceptable as a tutor at 40 tokens/s: over 15 minutes per problem with RSI off. This plan tests whether a stronger variation removes the quality gap, and whether the speed gap is a parameter-size limit.

🎯 Goal

Find a Qwen3.8-27B variation that handles the plotting rules and the page laws on the first pass, and measure its speed on the HPC.

🔧 Actions

🔍 Locate a coding-enhanced variation first. The task is code-heavy: Python checks, matplotlib figures, HTML composition.

🧪 If none fits, locate a math-enhanced variation. Use the same 7 test problems and the two transfer examples.

📈 Re-run the transfer. Use the same v17-derived instruction, so the model is the only variable.

🧮 Record the gate and the figures. A variation is accepted only if the gate passes and the learned plot recipe transfers.

💡 The parameter-size question. If a coding-enhanced variation fixes the plot transfer but not the speed, the limit is the parameter count. If it fixes both, the limit was the base model. Either result changes the next deployment plan.
