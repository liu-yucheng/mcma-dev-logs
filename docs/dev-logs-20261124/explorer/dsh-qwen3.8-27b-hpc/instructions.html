# Task Instructions

Solve all 24 problems in this directory. One subdirectory holds one problem, as
`<subdir>/problem.png`. You write the solution into `<subdir>/solution/` and
publish `<subdir>/solution.html`.

## 0. The budget

| Item | Value |
| --- | --- |
| Problems | 24 |
| Wall clock | 4 h |
| Per problem | 600 s, target 420 s |
| Decoder | 40 tokens/s, so 1,000 output tokens = 25 s |
| Output per problem | 8,000 tokens, including reasoning |
| Turns per problem | 6 |

Seven rules keep you inside the budget.

1. One message may hold several tool calls. Write every script of a problem in
   one message. Do not serialize what can go in parallel.
2. Chain shell commands with `;` and print the tail only:
   `python a.py; python b.py 2>&1 | tail -12`.
3. Never restate the problem. Never describe a plan. At most one sentence
   between tool calls. No summary before the last turn.
4. Never open `solution.html` (about 800 KB). Never print a Base64 payload.
5. Two attempts on one script. On the third failure, simplify the math, keep a
   value you can print, and move on.
6. Do not read this file again, and do not list the workspace twice.
7. If a problem passes 540 s (compare `date +%s`), skip the figure, finish the
   page, run the gate, and go to the next problem.

## 1. The tools are built. Do not rebuild them.

| Path | Use |
| --- | --- |
| `tools/render.py <subdir>` | Builds `<subdir>/solution/solution.html` from `<subdir>/solution/body.html`. Inlines KaTeX, the fonts, and every `FIG:` image. |
| `tools/check.py <page>` | The release gate. Prints one line per defect class, then `PASS` or `FAIL`. |
| `tools/katex/` | Offline KaTeX 0.16.47. No network is needed. |

You write four things per problem: the step scripts, at most one figure script,
`solution/body.html`, and `solution/NOTES.md` (three lines).

Never write CSS, `<head>`, `<script>`, or Base64 text. `render.py` adds all of
them. A hand-written `<head>` is a defect, not an improvement.

## 2. One problem in six turns

| Turn | Action |
| --- | --- |
| 1 | Read `problem.png`. Nothing else. |
| 2 | Write every `part<i>_step<j>.py` in one message: 3 steps, 4 when the problem has two parts. |
| 3 | Run them in one command, tail 12 lines each. Fix only a traceback line. |
| 4 | Write `body.html`, and one figure script when the problem names a region, a surface, or a space curve. |
| 5 | `python tools/render.py <subdir>; python tools/check.py <subdir>/solution/solution.html` |
| 6 | Repair only the defect that `check.py` named, then `cp <subdir>/solution/solution.html <subdir>/solution.html` |

A step script is 12 to 30 lines: a one-line docstring with the claim, the exact
computation, one numeric cross-check, one assertion, one `print`.

```python
"""Step 1.1: the cross section at x is a disk of area pi*x/4."""

import numpy as np
import sympy as sp

x = sp.symbols("x", positive=True)
print("area at x = 4:", sp.pi * 4 / 4)

step, axis = 0.01, np.arange(0, 1.5, 0.01)
grid = np.array([[a, b] for a in axis for b in axis])
count = int((grid[:, 0] ** 2 + grid[:, 1] ** 2 <= 1.0).sum())
print("grid area:", round(count * step**2, 4))

assert abs(count * step**2 - float(sp.pi)) < 0.03
print("PASS 1.1")
```

## 3. Math rules

Correctness and verification together carry 0.50 of the score. These rules
carry both.

1. No print, no sentence. Every number, shape, count, corner, and extremum on
   the page is printed by a script, and the verification line names that script.
2. Every assertion compares two independently computed values: an exact method
   (`sympy`, `fractions`) against a numeric method (grid, sample, Monte Carlo).
3. A banned assertion: a value against itself, a literal against a literal, or a
   hard-coded answer under the label of exact arithmetic.
4. The tolerance follows the method. A grid of step `h` gets a tolerance about
   `h`. One `1e-9` serves only a closed-form comparison.
5. Shape from the inequalities, not from the picture. Print the boundary of the
   section at three heights, and the corner list at each endpoint of the
   parameter. Call the section a point, a segment, or a face from that print.
6. A label on a surface satisfies that surface's equation. Compute the point.
7. Name a plane by the two axes that its points keep: a projection that drops
   `y` lies on `y = 0`. Give each surface its own direction.
8. Count what you claim: periods, rows, valleys, and repetitions come from a
   print inside a script.
9. Exact form first, then the decimal, then the unit.
10. Never carry a value from another problem, from the statement of an example,
    or from this file.

## 4. body.html: the only page file you write

Eight blocks, in this order: `h1`; `blockquote class="statement"` (two
sentences); a `Given`/`Find` table; a symbol table (symbol, meaning, unit); one
`section` per part, holding one `section` per step; `section class="answer"`;
`section class="notes"`.

A step is exactly this:

```html
<section><h3>Step 1.1: the cross section at $x$ is a disk</h3>
<p class="reason">The two inequalities give $y^2 + z^2 \leq x/4$.</p>
<div class="computation">$$ A(x) = \pi \frac{x}{4} $$</div>
<p class="result">The area at $x = 4$ is $\pi$, printed by <code>part1_step1.py</code>.</p>
<p class="verification"><code>part1_step1.py</code> compares the closed form with a grid count at three heights.</p>
<p class="mistake">A reader may take the slice for an annulus, but the limits give a disk.</p>
</section>
```

Rules for the file.

1. Put every math token inside `$...$` or `$$...$$`, including in a table cell
   and in a figure caption. Escape `<` and `&` in running text.
2. One `<li>` is one item, and it ends with a full stop.
3. At most 90 words per step, 120 lines per file, no inline styles.
4. A figure is `<figure><img src="FIG:part1_figure1.png" alt="..."><figcaption>Figure 1. ...</figcaption></figure>`.
   `render.py` inlines the PNG. Never write a Base64 string.
5. KaTeX accepts `\frac \sqrt \iiint \int \iint \partial \lim \sum \prod
   \theta \phi \rho \lambda \mu \leq \geq \neq \approx \cdot \times \vec \hat
   \bar \text \left( \right) \begin{pmatrix} \begin{aligned} \begin{cases}`.
   It rejects `\label`, `\eqref`, `\multicolumn`, `\begin{align}`, and
   `\begin{tabular}`. Use `\begin{aligned}` inside `$$...$$`, and build every
   table with HTML `<table>`.
6. A caption copy is plain text plus math. No `<br>`, no list.

## 5. Figures: at most one, 40 lines

Draw one only when the problem names a region, a surface, or a space curve. Keep
`figsize=(5, 3.6)`, `dpi=150`, one color map, wall `alpha=0.85`, and one label
per surface placed at a point that satisfies that surface.

```python
figure.canvas.draw()
renderer = figure.canvas.get_renderer()
artists = list(axes.texts) + ([axes.get_legend()] if axes.get_legend() else [])
for artist in artists:
    box = artist.get_window_extent(renderer)
    name = artist.get_text() if hasattr(artist, "get_text") else "legend"
    assert axes.bbox.x0 - 1 <= box.x0 and box.x1 <= axes.bbox.x1 + 1, name
    assert axes.bbox.y0 - 1 <= box.y0 and box.y1 <= axes.bbox.y1 + 1, name
```
