Experiment Report

Future Plans

The experiment is complete. The next step is to move the MCMA system from a research prototype to a dependable service. This page states the plans and the reason for each plan.

← ⌂ Overview Agents Experiment Results Briefing Results Explorer Demo Video Future Plans

🗺️ The Roadmap

🎯 The plans follow a firm order. Each plan prepares the next plan.

  1. 🧭 Confirm what is new. → Plan 1 (literature).
  2. 🚚 Move the base system to a newer framework. → Plan 2 (DeepSeek Harness).
  3. 🧰 Let the agent extend its own tool set. → Plan 3 (agent-developed tools).
  4. 🐧 Move the runtime to containers. → Plan 4 (Linux + Docker).
  5. 🗄️ Store the data in a database. → Plan 5 (Postgres).
  6. 🔌 Expose the tools by a standard protocol. → Plan 6 (MCP server).

🧭 Plan 1. Confirm the Innovation Points

🎯 Goal

Search the existing literature. Analyze the sources. Confirm what is new about math-capable multimodal agents in academia.

🔧 Actions

🛰️ Search. Collect the papers on math-capable multimodal agents, agent frameworks, and multimodal math reasoning.

📚 Analyze. Read each paper. Record its method, its tools, and its results.

⚖️ Compare. Compare the state of the art with the MCMA design.

✅ Outcome

A firm literature review. It will state the innovation points with evidence. It will show what is new and what is built on prior work.

🚚 Plan 2. Move to DeepSeek Harness

🎯 Goal

Move the base functions of the current agent to the DeepSeek Harness framework (github.com/deepseek-ai/deepseek-harness).

🔧 Actions

🕮 Study. Read the harness APIs and its tool protocol.

🔄 Port the loop. Move the agent loop to the harness.

🧩 Port the tools. Move the four base tools to the harness.

🧪 Re-run the suite. Run the 24-problem suite again. Compare with the recorded results.

✅ Outcome

An agent on a maintained framework. The re-run will confirm that the results do not change.

🧰 Plan 3. Let the Agent Build Its Own Tools

🎯 Goal

Use the DeepSeek Harness features. Let the agent develop small tools by itself. These tools will fill the gaps in the base tools.

🔧 Actions

🩺 Define the need. The agent finds a task that the base tools cannot do.

✍️ Write the tool. The agent writes the source code for the tool.

🧪 Test the tool. The agent runs the tool and checks the output.

📦 Register the tool. The agent stores the tool for later use.

✅ Outcome

A growing tool set. The agent does not wait for a hand-written tool to arrive.

🐧 Plan 4. Move to Linux + Docker

🎯 Goal

🎯 The agent now runs on Windows on a bare metal hardware. The goal is to run the agent on Linux inside Docker containers.

🔧 Actions

🖥️ Move the runtime. Install the tool chain on Linux.

📦 Build the image. Put the agent and its tools into a Docker image.

🔁 Run in a container. Run the suite in the container. Confirm the results match.

📜 Keep it reproducible. Record the build files and the version pins.

✅ Outcome

A reproducible runtime. It is ready for service-based deployment.

🗄️ Plan 5. Store Data in Postgres

🎯 Goal

The agent now stores data directly in the PC filesystem. The goal is to store the data in a Postgres database with a standard management method.

🔧 Actions

📐 Design the schema. Define the records for the run sessions and the results.

🔌 Connect the server. The agent server writes to Postgres instead of files.

🗂️ Add migrations. Manage the schema changes in version control.

💾 Add backups. Store the data copies on schedule.

✅ Outcome

A typed, searchable, dependable data store. It replaces the flat files.

🔌 Plan 6. Expose the Tools as an MCP Server

🎯 Goal

The base tools are now the Extensions of the DeepAgents built-in tools. The goal is to rebuild all base tools as one Model Context Protocol (MCP) server. The MCP protocol is a standard interface for tool calls.

🔧 Actions

🧩 Refactor. Move each base tool into a service method.

🧭 Expose the protocol. Publish the tool list and the call interface through MCP.

🔗 Connect the client. The agent calls the server through the MCP client.

🧪 Re-run the suite. Confirm the tools behave the same as before.

✅ Outcome

Any MCP-capable agent can reuse the tools. The tool interface is no longer tied to DeepAgents.
