Literature Review — Chapter 2

The Architecture of Autonomy: Agentic Frameworks and Their Limitations

🤖 A math-capable multimodal system is not just a model. It is an agent. An agent perceives, reasons, and acts. The current literature on agentic architectures sets the context for autonomous capability. It also shows gaps in how these architectures are applied to complex mathematical tasks.

🧩 2.1 Decomposing problems into executable steps

A dominant paradigm in agentic reasoning is to break a complex problem into a sequence of simpler, often executable, steps. This neuro-symbolic approach improves interpretability and reliability.

Code-as-policy

Systems such as ViperGPT [27] and VisProg [28] pioneered the idea of having an LLM generate code (for example, Python) that calls APIs or specialist models to solve a visual task. This approach answers a key weakness of end-to-end models: the entanglement of visual processing and logical reasoning [29]. By generating an explicit program, the agent's reasoning becomes transparent and debuggable. The use of pyplot and PGFplots code generation fits this paradigm well.

Multi-agent systems

More complex tasks often benefit from a society of collaborating agents. Frameworks such as MAGMA-Edu [30] and MatPlotAgent [31] use multiple specialized agents. For example, MAGMA-Edu uses a “Code Generator Agent” to create visualizations with matplotlib.pyplot [32]. MatPlotAgent uses a “visual agent” to analyze plots and a “code agent” to write and debug the plotting code [33]. This modularity allows more specialization and more robustness.

✏️ 2.2 The emerging paradigm of sketching as a reasoning tool

A particularly relevant line of research for surface-sketching is the use of a “sketchpad”. It is not just an output canvas. It is an external cognitive tool that aids reasoning. This mimics how humans draw diagrams to think.

Visual sketchpads

Visual Sketchpad [34] and Sketchpad [35] address a major gap in MLLMs: the lack of an external working memory to offload visual-spatial information. These frameworks let an agent “draw” auxiliary elements such as lines, boxes, or marks onto a canvas [36][37]. The key insight is that the act of sketching is part of the reasoning process itself — a “visual chain of thought” [38]. This approach has shown real performance gains on math problems that involve geometry and graphs [39].

Related systems in the same line of work: SketchAgent (arXiv:2411.17673) [40], TalkSketch [26], and reflection-in-action ideation frameworks [27].

Research gap: from 2D auxiliary marks to 3D generative sketching

The current state of agentic sketching focuses on adding 2D auxiliary marks to existing images to solve a problem. This is fundamentally different from a tutoring agent's task: generating a complex 3D surface sketch from scratch based on a mathematical description (for example, an equation z = f(x, y)).

❓ Open problem: How can agentic architectures be extended to support generative 3D sketching as a reasoning process? This would involve more than plotting the final surface. The agent might sketch contour lines, gradient vectors, or cross-sections as intermediate reasoning steps. All of these would be orchestrated by the agent.

🕳️ 2.3 Research gap: adaptive and dynamic agent architectures

Current multi-agent systems often rely on predefined workflows and fixed agent roles. This rigidity is a major limit when facing the open-ended nature of advanced mathematics.

The SkillGraph findings

The SkillGraph paper [41] identifies two critical gaps in multi-agent systems:

  • Fixed topologies. Agent graphs cannot adapt to the specific demands of a new task.
  • Skill stagnation. Agents cannot refine their skills or heuristics on their own when they meet novel problems or “blind spots.”

This applies directly to a tutoring agent. An advanced calculus problem may need a sequence of actions that a fixed architecture cannot foresee. The agent may first manipulate symbols (with a CAS tool). It may then draw a 3D plot (PGFplots). It may then analyze the plot to find a feature. Finally, it may draw a 2D contour plot (pyplot) to explain that feature to the student.

❓ Major research question: How can we develop dynamically reconfigurable multi-agent architectures for mathematical tutoring — where the agent team and their collaboration workflow adapt in real time to the complexity of the problem and the pedagogical needs of the student?

An agent with a diverse toolset — symbolic, 3D generation, contour mapping — provides an ideal platform to explore solutions to this “skill stagnation” problem.
