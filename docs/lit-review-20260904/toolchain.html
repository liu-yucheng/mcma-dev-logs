Literature Review — Chapter 3

The Visualization Toolchain: A Tale of Two Tools (pyplot vs. PGFplots)

🐍 The ability to use both matplotlib.pyplot and PGFplots is one of the most distinctive features of the agent under review. The literature shows a sharp difference in how these tools are adopted within agentic systems. With this difference comes a large, untapped research area.

🐍 3.1 The dominance of matplotlib in agentic workflows

The search results consistently show that when autonomous agents need to generate plots, they almost always turn to Python's matplotlib library.

Direct code generation

Systems such as MAGMA-Edu [42], AXPO [43], and MultiVis-Agent [44] all show agents that write and run Python code directly with matplotlib.pyplot. The generated code is explicit and imperative. It uses commands such as plt.plot(), plt.text(), and plt.savefig() [45].

Iterative refinement

The revision process for matplotlib plots is also well documented. MultiVis-Agent includes specific agent actions for generate_visualization_code and modify_visualization_code. It has an evaluation loop. This loop runs the matplotlib code (execute_matplotlib_code) and gives feedback for refinement [46]. Similarly, the chart-plot agentic system uses matplotlib code generation inside a render loop. It uses this to reach publication-quality charts through iterative editing [47][48]. PlotGen [49] and MatPlotAgent [50] describe multi-agent architectures. In these, feedback (numeric or visual) triggers revisions in the matplotlib code.

Why matplotlib dominates

The reason for matplotlib's dominance is clear. It fits neatly into the code-as-policy paradigm that LLMs prefer. The feedback loop is simple:

  1. 🔎 The LLM generates Python code.
  2. ⚙️ A code interpreter runs it.
  3. 📤 The output (an image file or an error message) returns to the agent.
  4. 🔄 The agent revises the code based on the feedback.

📄 3.2 The research void: agentic control of PGFplots

In sharp contrast to matplotlib, the provided literature contains no example of an autonomous agent using PGFplots for generative and revision tasks in education. Repeated and targeted queries on this topic found no such system.

What the literature shows

The search results reference PGFplots only in general terms. They call it a capable LaTeX package for creating high-quality scientific plots [51][52][53]. One older paper from 2007 describes a web service for automating PGFplots generation via JSON-RPC. This is not an autonomous LLM-based agent. It has no revision or tutoring capability [54].

What the literature is missing

No paper describes an agent that:

  1. ✍️ Writes LaTeX code that uses the pgfplots package to define a mathematical plot.
  2. 🛠️ Compiles the LaTeX document to generate a PDF or image.
  3. 👀 Reads the visual output or the compilation logs to judge the result.
  4. 🔄 Revises the PGFplots LaTeX code on its own to fix errors or make improvements.

This is a clear research gap. PGFplots offers better typographic consistency and quality for publication-ready figures inside scientific documents. This makes it a desirable tool. However, its declarative, compilation-based nature is a harder challenge for agentic control.

🕳️ 3.3 Open problems from the PGFplots gap

The ability to use PGFplots opens a rich line of research questions that the community has not yet addressed:

⚙️
Building robust agentic workflows for declarative languages

The core challenge is to create a reliable reasoning and action loop for a compiled language such as LaTeX. An open problem is: What is the best agentic architecture for controlling PGFplots? Does it need a complex chain of parsing compiler errors? Does it need a vision agent to “look” at the output PDF and give feedback? The chart-plot system uses LaTeX for layout but matplotlib for the actual plot [55][56]. This suggests that researchers have so far avoided the complexity of controlling the LaTeX graphics layer itself.

⚖️
Comparing toolchains

An agent with both tools is well placed to answer: What are the trade-offs between an imperative library (matplotlib) and a declarative package (PGFplots) for autonomous mathematical visualization? This research could explore reliability, output quality, ease of revision, computational overhead, and the types of errors the agent makes with each tool.

🧠
Hybrid tool use

A more advanced question is: How can an agent learn to choose the best tool for the job? Perhaps matplotlib is better for quick, exploratory sketching. PGFplots might be reserved for the final, high-fidelity figure in a report. This needs a higher level of metacognition and planning.

well covered 🐍 matplotlib

Direct code generation, render loops, numeric and visual feedback, multi-agent revision. This is the dominant paradigm in agentic plotting.

research void 📄 PGFplots

Only general references and a 2007 web service. No autonomous compilation, log parsing, or revision loop exists in the literature.
